# Task 10 — Expectations versus execution

Run `python benchmark.py` and paste your own actual totals and times into the report. The exact elapsed times and object sizes depend on the computer, operating system, and Python build; do not copy invented timings. Float summation is generally faster but can accumulate tiny representation errors. Decimal is usually slower but represents base-ten decimal amounts reliably when constructed from strings. Both are O(n) time; with the input list included, storage is O(n), while the running accumulator is O(1).

The policy should specify whether each farmer payment is rounded to paise and then summed, or whether unrounded values are summed and rounded once. Since each farmer's bank payment is normally individually payable to paise, calculate and round each payment to two decimals, then sum those payable amounts exactly. A cache/dictionary for repeated `(fat, snf)` pairs gives average O(1) lookup after precomputation but costs O(k) extra space for k unique pairs. Recalculation is also O(1) per entry, so caching is useful only if rate calculation is expensive and pairs repeat frequently; measure with `timeit` or `perf_counter`.
